# AI and Model Quality Trend — Short Version

## Element shown in the approved main view

| Property | Value |
|---|---|
| Section | AI and model quality |
| Element | 30-day three-series score trend |
| Series | Groundedness, Response Coherence, Relevance Quality |
| Scale | Shared `1–5` axis |
| Scope | Last 30 days, business unit, project, channel |

All chart values are illustrative. A shared chart is permitted only because these three mapped evaluator scores are described as Likert `1–5` values; it must not contain the `0–1` MLflow score.

## Persona and KPI support

| Series | Fields | Documented calculation |
|---|---|---|
| Groundedness | `evaluation_run_id`, `groundedness_score`, `groundedness_result`, `completion_id`, `finish_reason` | `AVG(groundedness_score)` |
| Response Coherence | `coherence_score`, `coherence_result` | `AVG(coherence_score)` |
| Relevance Quality | `relevance_score`, `relevance_result` | `AVG(relevance_score)` |

Score fields are evaluator outcomes; result fields are pass/fail signals and are not plotted as the numeric score.

## Semantics, calculation, and time bucketing

The chart answers: **Are the comparable evaluator scores changing over time for the selected technical scope?** Higher score direction is likely but threshold interpretation is unapproved.

```text
score_point(metric, bucket) = AVG(valid metric_score in bucket)
display_point               = round(score_point, approved_precision)
```

Example: groundedness scores `4, 5, 4, 3` in one bucket yield `4.0`. The trend must average evaluation-level records (or an approved request-level roll-up), not daily averages of unequal-sized samples.

## Recommended eligible population

- Include only scores generated by the approved evaluator/version and chosen population (for example online production); do not mix offline/test results without approval.
- Use `completion_id` or an approved request/evaluation key to deduplicate repeat logs. Decide whether multiple evaluations for one completion are averaged or separately counted.
- Exclude invalid/missing scores and report coverage separately; missing evaluation is not a low score.
- Apply global filters only after reliable attribution to the evaluated interaction.

## Assumptions and client questions

Assumptions: all three scales remain 1–5, daily buckets are proposed for 30 days, and Splunk/API returns one normalized series per metric.

Questions: Which evaluator/version and population are approved? Are scores per turn, completion, request, or run? Can versions/scales be combined? What coverage/freshness is required? What timezone/bucket/rounding rules and score thresholds apply? Can every evaluation honor all global filters?
